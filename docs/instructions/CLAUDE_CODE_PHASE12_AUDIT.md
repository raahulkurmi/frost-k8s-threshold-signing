# Phase 12: Final adversarial audit (fresh session)

You are an adversarial reviewer, not the author. You did not write this code. Assume the code, tests, docs and reports contain mistakes until you prove otherwise with evidence. Your job is to find every loose end before a conference reviewer or a PhD committee does.

Read first, in full: docs/instructions/ (all files), NOTES.md, README.md, docs/THREAT_MODEL.md, reports/ (all files).

## Rules

1. Report first, fix later. In passes A–J, do not change code, tests or docs. Only write to reports/audit/.
2. Every finding needs: ID, severity (critical / high / medium / low / info), file:line or test ID, evidence (exact command and output), why it matters, suggested fix.
3. Never accept a claim because a document says it. Re-derive it from code or a re-run.
4. Never accept a test because it passes. Read it and prove it can fail (Pass C).
5. If something cannot be verified in this environment, say "UNVERIFIED" with the reason. Do not guess.
6. Do not print secret values. Do not rewrite git history. Do not force-push.
7. Work from a fresh clone of fix/threshold-rsa at the freeze commit, in a new directory, not the existing working tree.
8. No AWS resources during the audit.

## Pass A: Fresh reproduction

- Fresh clone; run make repro exactly as documented, with no manual fixes. If no Linux host is available locally, trigger the repo's repro GitHub workflow on the freeze commit and use its result. If any step needs a manual action not in the docs, that is a finding.
- Compare every number in README.md, docs/THREAT_MODEL.md, reports/*.md against committed results or a re-run. Any number that cannot be regenerated by a script from committed raw data is a finding.

## Pass B: Invariants I1–I10

For each invariant: restate it, locate the code that enforces it, locate the test(s) that check it, run them, and state whether the test would actually fail if the invariant were broken. Output a table.

## Pass C: Test strength (mutation testing)

- Run a Go mutation tool (e.g. go-mutesting or gremlins) on: internal/signer, internal/policy, internal/coordinator, internal/grpcserver, internal/dealer, internal/keyshare, internal/wire, internal/tlsconf.
- Additionally, make these manual mutations one at a time on a scratch branch, run the full test suite, and record which test catches each (a mutation no test catches is a high finding):
  1. Coordinator skips per-share verification (strict mode).
  2. Coordinator skips final signature verification.
  3. Coordinator does not dedupe share IDs.
  4. Coordinator does not bounds-check share ID.
  5. Coordinator accepts a share whose ID does not match the signer's mTLS identity.
  6. Signer accepts a pre-hashed input.
  7. Signer skips the policy check.
  8. Policy accepts case-variant duplicate keys (revert N14).
  9. Policy iat skew check removed.
  10. Signer loads more than one share.
  11. Coordinator package imports a secret share type.
  12. FetchKeys returns a key other than the group key.
  13. Admission control never sheds (revert N48).
  14. Cancellation check removed (revert N46).
  15. Caller receives detailed policy reason (revert N33).
  16. mTLS client-SAN check on the coordinator removed.
  17. QUORUM_ABORT defaults to on (revert N82).
- If you decline any mutation for any reason, skip it, record it as "not executed" with a one-line reason, and continue with the rest. C3 (collusion) is already recorded as a boundary statement backed by T2 + T1/E2; do not re-attempt it.
- Report per-package coverage (go test -cover) and list every exported function with zero coverage.

## Pass D: Fuzzing

Write Go native fuzz tests (in reports/audit/fuzz/, not in the main tree during the audit) for every parser that touches network input: JWT header parsing, claims/policy decoding, sign-share request body, share response decoding, X-Frost-Deadline-Ms parsing, public-meta and share file loading. Run each for at least 10 minutes. Any panic, hang, or accepted-but-invalid input is a finding.

## Pass E: Security review

Read, line by line: signer handler, policy, coordinator collection/verify/Join, dealer, tlsconf, keyshare loading, Vault loading, priority key handling, nginx config, compose files, multihost scripts, systemd units, firewall rules. Look specifically for:
- parser differentials between signer policy and the apiserver's go-jose v2 verifier (beyond N14);
- fail-open paths, default values that weaken security, env vars that disable checks;
- panics reachable from network input;
- identity binding gaps (signer ID <-> mTLS cert <-> share index <-> kid; coordinator replica identity);
- TOCTOU on key/share files;
- secrets in logs, audit logs, error messages, core dumps, env vars, process args;
- resource exhaustion (body size, header size, connection count, queue growth, goroutine leaks);
- anything letting a coordinator obtain a signature on claims the policy should reject;
- test-only build tags (testmalicious, policy-disabled) leaking into any shipped binary or image.

## Pass F: Cryptographic correctness

- Confirm the Shoup scheme usage: padding (EMSA-PKCS1-v1_5, SHA-256), Delta = n!, share verification proofs, combine, modulus size exactly 2048 bits, e = 65537.
- Confirm the dealer never writes the full private key, and that key generation uses crypto/rand.
- Confirm the N5 tcrsa hazards are mitigated in the coordinator, each with a test.
- Confirm the signature produced is byte-identical across all 10 subsets in a fresh run.
- State plainly what is assumed rather than verified (tcrsa correctness, no side-channel review, trusted dealer).

## Pass G: Claims audit (docs vs reality)

- Re-verify every row of reports/CLAIMS_AUDIT.md and reports/REVIEW_RESPONSE.md against code or committed results. Flag any row whose evidence does not support its verdict.
- Scan README.md, docs/THREAT_MODEL.md, reports/INDEPENDENCE.md, reports/PAPER_INPUTS.md for every sentence making a security, performance or correctness claim. Each must have evidence. List unsupported ones.
- Check wording discipline: nowhere may Level 1 be called "independence"; nowhere may emulated latency be presented as real RTT; nowhere may preliminary arm64 numbers be presented as final; the upstream Kubernetes issues (#141669, #141670) must be framed only as "found and reported upstream; documentation gaps; awaiting triage; community fixes proposed, none merged", never as fixed by maintainers or as defects in KEP-740; the overload-control work (v1, v2) must be framed as evaluated and not adopted, never as a working fix.
- Check every reviewer point R1–R18 (and any added from the original 6B/6C text) has status and evidence.
- Evidence existence check: extract every file path, results directory, log name, commit hash and test name cited in NOTES.md, README.md, docs/, and reports/. For each, verify it exists in the git tree at the freeze commit (or the commit exists). Earlier in this project 33 cited evidence logs were silently never committed; any cited evidence missing from the repo is a high finding.
- Re-check every rule change made mid-run (e.g. the L2 re-run rule after the Wi-Fi drop, N60) and every test-assertion change (e.g. N56, N82): was the change justified before seeing the result it affected, and is the original result still kept? Confirm the v2 pre-registration (293a919) predates the v2 implementation (d07a8e7) and all v2 data.

## Pass H: Code quality

- go vet, staticcheck, govulncheck, gosec, golangci-lint (with a reasonable default config): paste output, triage every finding.
- Dead code, duplicated logic, unchecked errors, inconsistent error wrapping, magic numbers without named constants, misleading names, comments that contradict code.
- Shell scripts: shellcheck on every .sh; check set -euo pipefail, quoting, bash-version assumptions (N42-style issues).
- Dockerfiles: pinned base images by digest, non-root user, no build secrets.
- CI: actions pinned by SHA, no secrets exposure, steps actually run the tests they claim.

## Pass I: Dependencies and licensing

- Every direct and indirect dependency with version and license (go-licenses or equivalent). Flag anything incompatible with the repo license.
- tcrsa pinned exactly at v0.0.5; NOTICE and README licensing/patent text present and accurate.
- No replaced or vendored modules that differ from upstream without a note.

## Pass J: Repository hygiene

- gitleaks on tree; custom scan for share-shaped files, PEMs, .enc, binaries (file on every tracked file).
- .gitignore covers every generated artifact (secrets, run, audit, bin, results scratch).
- reports/HISTORY_PURGE.md lists everything that must be purged from history, and nothing sensitive is missing from it.
- No leftover debug code, commented-out blocks, personal paths (/Users/...) in shipped files.
- The word "CleanStart" appears nowhere in the repo.

## Output

1. reports/audit/AUDIT.md: all findings, sorted by severity, with a summary count per severity and per pass.
2. reports/audit/MUTATION.md: every mutation, whether caught, by which test.
3. reports/audit/FUZZ.md: every fuzz target, duration, result.
4. reports/audit/CLAIMS_RECHECK.md: every claim sentence found, evidence, verdict.
5. reports/DEFENSE_BRIEF.md: one page, plain English, for a PhD interview:
   - the original bug and how it was found;
   - why FROST cannot work with Kubernetes today (allow-list);
   - how Shoup threshold RSA works in 5 sentences;
   - what the system protects against and what it does not (online oracle, dealer trust, co-located signers, single account);
   - the N14 parser-differential bug in 3 sentences;
   - the quorum-waste finding and the two pre-registered overload-control iterations (what was tried, why neither was adopted, the measured trade-off) in 5 sentences;
   - the 8 hardest questions an expert would ask, each with a short correct answer.
6. A prioritized fix list. Stop and wait for my approval before fixing anything.

## After approval: fix loop

- Fix every critical and high finding; medium/low either fixed or explicitly accepted with a written reason. Each fix names the finding it fixes (code freeze rule, N83).
- After each fix, re-run every gate the fix could affect, and re-run the mutation that motivated it.
- Append a "resolution" column to AUDIT.md (commit hash, test that now covers it).
- Final: fresh-clone repro once more (local or the GitHub repro workflow); paste output.

Exit criteria (all required): zero open critical/high; every executed mutation in Pass C caught; no fuzz crash; every claim sentence has evidence; fresh-clone repro passes.

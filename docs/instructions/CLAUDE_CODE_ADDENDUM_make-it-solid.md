## Phase 9: Adversarial compromise tests

Addresses reviewers 6A and 6C: stopping containers tests availability, not compromise.

Keep all crash/stop tests, but label them "availability" everywhere. Add these as "compromise" tests:

- C1 Malicious signer (exists as T5): garbage share, share for a different input, share with a spoofed Id, oversized payload, slow-loris response. Coordinator excludes, attributes, never panics, never hangs past deadline.
- C2 Two compromised signers + full coordinator control: attacker holds 2 real shares and can send arbitrary requests to the 3 honest signers. Show: (a) policy-violating claims (wrong iss, disallowed aud, over-max exp, malformed sub, case-variant duplicate keys per N14) are refused by every honest signer, so no valid token forms; (b) policy-compliant claims CAN be obtained while the attacker controls the coordinator. State (b) explicitly as the online-oracle limitation.
- C3 Collusion at threshold: 3 signers with policy disabled (test-only build tag) sign arbitrary claims; a forged token passes TokenReview. This confirms the threat-model boundary: t colluding signers can forge. Label it as a boundary confirmation, not a vulnerability.
- C4 Compromised coordinator persistence: after the coordinator is "compromised" (attacker copies its whole filesystem and memory-visible config) and then removed, the attacker cannot mint any token offline. Prove it by scanning a coordinator container export for any share or private key, and by showing no offline signing path exists.
- C5 Stolen single share + public metadata offline: cannot produce a valid signature for any message (extend T4 to every single share).
- C6 Replay of an old signing request to signers: document behaviour (RSA shares are deterministic; replay yields the same share for the same input). Show the policy iat skew check rejects stale requests, and record the window.
- C7 Rate-limit abuse: a flood from a compromised coordinator is throttled per signer. Record the limit and what a legitimate cluster needs.

Gate 9: C1–C7 pass or are documented as boundary confirmations, with output pasted. THREAT_MODEL.md has a table: attacker capability -> what they get -> test ID.

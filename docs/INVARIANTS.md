# Invariants I1–I10

The code, tests, Dockerfiles and reports cite these invariants by number ("T1 (I1, I2)",
"I3", …). This file is their one definition (Phase 12 audit finding B-1). The prompt that first
stated them was never committed; the wording below is reconstructed from every citation in
the repository and was checked against the code in the audit (`reports/audit/AUDIT.md`, Pass B).

"Mutation" names a source edit that breaks the invariant, from `reports/audit/MUTATION.md`.
Each listed test fails under that mutation, which shows the test can actually catch a
violation and does not merely pass.

| ID | Invariant | Enforced by | Tests | Mutation evidence |
|---|---|---|---|---|
| **I1** | Every issued token is an RS256 JWT whose signature is combined from at least t = 3 signature shares; the system has no single-key signing path. | `internal/coordinator`: `Coordinator.Sign` (combine with tcrsa `Join`, then `rsa.VerifyPKCS1v15` against the group key before returning); `internal/jwtfmt` (the one RS256 header); no private-key type in the coordinator (I3) | T1 `TestIssuedJWTVerifiesWithFetchKeysOnly`, T2 `TestAllThresholdSubsetsIdentical`, `TestSignProducesStandardRS256`; e2e E1, E2 | M2 (no final verification), X1 (non-canonical header): caught |
| **I2** | Verifiers obtain the public key only from FetchKeys, and FetchKeys returns exactly the threshold group key, with kid = base64url(SHA-256(PKIX)[:16]). | `internal/grpcserver`: `Server.FetchKeys`; `internal/keymeta`: `Parse` (kid bound to the key) | T1, `TestFetchKeysPKIXRoundTrip` (grpcserver and cmd/dealer), `TestCoordinatorMetaIsGroupKey`; e2e E5 | M12a/b/c (extra key, other key, wrong kid): caught |
| **I3** | The coordinator holds only public metadata: no secret share and no private key, in code, in its image or on its host. | `cmd/grpc-proxy` loads only `internal/keymeta`; the package rules in `internal/keyshare` and `internal/prioritykey` | T12 `TestCoordinatorHasNoSecretTypes`; T13 `scripts/check-images.sh`; L4 (multihost) | M11 (coordinator imports `keyshare`): caught |
| **I4** | Each signer holds exactly one share, its own (index = signer id, bound to its verification key), delivered at runtime; images contain no secret; no host holds t or more shares. | `cmd/signer`: `load` (one `SHARE_FILE`, one `Share` field); `internal/keyshare`: `Parse` (one JSON object, index, kid, v^sᵢ = vkᵢ); Dockerfiles; `deploy/multihost/topology-guard.sh` | `TestShareFileMustNameExactlyOneFile`, `TestMultiShareFileRejected`, `TestShareFilesEachHoldExactlyOneShare`, `TestWrongShareIndexRejected`, `TestCorruptedShareRejected`, `TestSignerNewRejectsForeignShare`, `TestTopologyGuard`; T13; L3, L4 | M10a, M10b, X6: caught; E-2 guard negative control |
| **I5** | Fewer than t valid shares never yield a token. | tcrsa `SigShareList.Join` (rejects fewer than K shares); `Coordinator.Sign` threshold logic and final verification | T3 `TestBelowThresholdFails`, `TestBelowThresholdFailsWithAbort`, T4 `TestTwoSharesCannotForge`, `TestBelowThresholdSigners`, `TestThreeMaliciousFails`; spike `TestBelowThresholdFails` | X16 (threshold t−1): caught |
| **I6** | Signing is deterministic: every t-subset of shares yields a byte-identical signature for the same input. | RSASSA-PKCS1-v1_5 and the Shoup combine (mathematics, not code) | T2, spike `TestAllThresholdSubsetsIdentical` | not mutable in code; re-verified in the audit (all 10 subsets identical, and identical to `crypto/rsa`) |
| **I7** | A bad share is excluded and attributed to the authenticated signer that sent it; the combined signature is verified before anything is returned. | `Coordinator.Sign` (strict verify-until-t; optimistic verify-after-failed-combine; suspects; breaker); `Coordinator.fetch` (share id = mTLS identity, response `signer_id` and `request_id` checked); `wire.SigShare.ToTcrsa` (id and value bounds) | T5 `TestMaliciousSignerExcluded` (`-tags testmalicious`), `TestMaliciousShareExcludedAndAttributed`, `TestShareIDBoundToMTLSIdentity`, `TestJoinOutOfRangeIDs`, breaker tests | M1, M2, M4a, M5a, M5b, M5c: caught |
| **I8** | A signer hashes and PKCS#1 v1.5-pads the full signing input itself and never signs a caller-supplied digest or padded block. | `internal/signer`: `Server.SignShare`; `internal/wire`: `SignShareRequest` (unknown fields rejected) | T6 `TestSignerRejectsPrehashedInput` (internal/signer and test/) | M6a, M6b: caught |
| **I9** | Every binary fails closed: any missing or invalid configuration aborts startup, and there is no plaintext or permissive mode. | `cmd/*/main.go` `load`; `policy.New`, `keymeta.Parse`, `keyshare.Parse`, `internal/tlsconf`, `internal/vaultclient` (https only, no cross-host redirects) | T8 `TestCoordinatorFailsClosed`, `TestSignerFailsClosed`, `TestSignerBinaryFailsClosed`, `TestPolicyConfigFailsClosed`, `TestAdmissionConfigFailsClosed`, `TestLoadDefaults`, `TestQuorumAbortDefaultsOff`, `TestNoCrossHostRedirect`, the `VAULT_ADDR` scheme tests | X15 (plaintext TCP), M17a (default flipped): caught |
| **I10** | The working tree, including ignored directories, never contains secret or key material. | `test/e2e/run.sh` wipe-on-exit trap; `.gitignore` | T11 `TestNoSecretsInTree` (gitleaks), `TestNoKeyMaterialFilesInTree` | X17 (a share-shaped file in ignored `secrets/`): caught |
